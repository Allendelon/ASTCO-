# Arabic and English (ADR-006)

## What is translated where

| Text | Lives in | Why |
|---|---|---|
| Interface labels, messages | `app/public/i18n/{en,ar}.json` | Product text, same on every project |
| Server errors | Same catalogs, `err.<code>` | Server sends `{ code, params }`, English `error` for API clients |
| Code lists, suitability descriptions | Database, `description` / `description_ar` (migration 0013) | Project data: each project may reword its own |
| Document titles, subjects, comments | As entered | User content is never machine-translated |

## Rules

- **Always Gregorian dates and Latin digits,** in both languages (`ar-SA-u-ca-gregory-nu-latn`). Contract dates are Gregorian, and digits must match the ISO 19650 codes beside them. A Hijri display is an optional later addition, never a replacement.
- **Codes are left-to-right islands.** Document numbers, revisions, suitability and review codes, hashes, IFC GlobalIds and filenames go through `ltr()` (`<bdi dir="ltr">`). The title block is `direction: ltr` because the code it spells reads that way.
- **Names of unknown direction placed inline go through `bidi()`,** or a Latin name pulls the Arabic text beside it into its run. User-written paragraphs and inputs get `dir="auto"`.
- **Use `tn()` for counts.** Arabic has six plural forms (zero, one, two, few, many, other).
- **Never build sentences by concatenating translated fragments.** Use one key with `{placeholders}`, so each language can order the words itself.
- **Don't set `letter-spacing` on Arabic text.** It breaks the joins between letters.

## Tests (`app/test/i18n.test.js`)

- **Both catalogs have the same keys and the same placeholders.** Plural forms are exempt, since Arabic may leave the number implicit.
- **Every server code and field has an entry.** So does every message the database raises.
- **Every `t('…')` key in the browser code exists.**

## Native review needed

The Arabic is a first translation. Before a customer launch, a native-speaking information manager must confirm the construction and ISO 19650 terms. In particular:

- suitability descriptions (S0–S4, A1–A3, B1–B2, CR);
- review codes A–D;
- "transmittal" (الإرسالية), "originator" (الجهة المُعِدّة), "volume" (المجلد);
- inspection types (WIR/MIR).

Terms used by the Saudi client's own contract documents take precedence.
