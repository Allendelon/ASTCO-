# Failure hunt: fault injection against the running stack

**Setup:** PostgreSQL 16 and the app in production mode (`NODE_ENV=production`), connected as the restricted `cde_api` role, with seed data. Each experiment was run against the live stack and re-run after its fix. Every fix has a regression test in `app/test/resilience.test.js` or `db/tests/test_schema.sql`. Tests E1, E3, E5 and E7 were mutation-checked: they fail when their fix is removed.

| # | Experiment | Before | Root cause | After |
|---|---|---|---|---|
| E1 | Another session holds a lock on `cde_documents` for 40 s | **Whole app down:** every request hung, including `/api/me` and `/healthz`; nothing logged | No statement, lock or pool-wait timeout. Blocked requests held all 10 pooled connections, so requests that never touch the table queued forever too | Affected requests get `503` + `Retry-After` in about 5 s; the rest of the app and `/healthz` keep answering |
| E2 | Restart Postgres under traffic | Recovered within 0.5 s of the database returning; during the outage, `500` responses and a full stack trace per request | Connection errors were treated as server bugs | `503` + `Retry-After`, one log line per request |
| E3 | Kill database connections mid-transaction (failover, `pg_terminate_backend`, network drop) | **The Node process crashed** (`Unhandled 'error' event`); the app was down until restarted | pg-pool removes its error listener from a client while it is checked out (`pg-pool@3.14.0` `_acquireClient`, line 344). `withTx` added none, so the Client's `'error'` event had no listener. ## Edge cases found, not changed

- **"Overdue" uses UTC dates.** The database runs in `Etc/UTC`. At 01:30 in Riyadh on 1 Oct it still considers the date to be 30 Sep, so transmittals due on 30 Sep are flagged overdue 3 hours late. For a KSA-only deployment, set `ALTER DATABASE … SET timezone = 'Asia/Riyadh'`. For multi-region, add a project time zone. Either way this is a product decision, so it was left as is.
- **Session expiry during a long upload.** The session is checked when the upload starts, so the upload completes. If the session expires before the revision is created, the user must sign in again. The stored upload stays claimable by the same user for 24 hours, but the page has lost the upload's reference and they must upload the file again.
- **Every document page view is logged as a download,** because the preview loads the file. This is correct auditing, but it will dominate the audit table's size (see R2-07).
